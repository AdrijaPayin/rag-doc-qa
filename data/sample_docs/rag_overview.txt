Retrieval-Augmented Generation (RAG) is an approach that combines a retrieval system with a language model to produce answers grounded in external documents. Instead of relying only on what the model learned during training, RAG first searches a knowledge base for relevant information and then feeds that information to the model as context.

A typical RAG pipeline has three stages. First, documents are split into small chunks, usually a few hundred characters or tokens each, so that each chunk covers a focused piece of information. Second, each chunk is converted into a vector embedding using a model such as a Sentence Transformer. These embeddings are stored in a vector database like FAISS, Pinecone, or Chroma. Third, when a user asks a question, the question itself is embedded and compared against the stored chunk embeddings to find the most similar ones. These retrieved chunks are then passed to a large language model along with the original question, and the model generates an answer using that context.

The main benefit of RAG is that it reduces hallucination. Because the model is instructed to answer only from the retrieved context, it is less likely to invent facts that are not supported by any document. RAG also makes it possible to update the knowledge base without retraining the model. If a document changes, you simply re-index it, and the next query will retrieve the updated information.

FAISS, which stands for Facebook AI Similarity Search, is a library for efficient similarity search over dense vectors. It supports several index types. The simplest is a flat index, which performs an exact nearest-neighbor search by comparing the query vector against every stored vector. This is slower on very large datasets but is exact and simple to reason about, which makes it a good starting point for smaller projects.

Sentence Transformers are a family of models fine-tuned specifically to produce sentence-level and paragraph-level embeddings where semantically similar text ends up close together in vector space. The all-MiniLM-L6-v2 model is a popular lightweight choice because it produces 384-dimensional embeddings quickly while still capturing meaningful semantic relationships between sentences.

Retrieval quality is commonly measured using Recall@K, which checks whether the correct or relevant chunk appears within the top K results returned by the retriever. A high Recall@5 means that for most questions, the right piece of information is present somewhere in the top five retrieved chunks, even if it is not always ranked first.
